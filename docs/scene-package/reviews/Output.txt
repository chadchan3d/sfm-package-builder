## 3. Non-blocking corrections

These are listed roughly by priority. C1–C3 affect Stage 0 and should land before it starts.

**C1. No rule for using existing evidence** (§9, Stage 0, §11; prompt item 8). Revision 2 never says whether existing evidence can satisfy a gate. Several parts of the text, read strictly, would force duplicate experiments:
- The gates are written as experiments to perform ("Capture…", "Open…", "Test…").
- Evidence must record "tool version/hash and exact inputs."
- §11's fixture manifest requires fields that older qualification records won't have, such as ordered provider labels and expected dispositions.
- "Never carry old results forward as reruns" is scoped to build/test commands, but reads as general.

*Smallest fix:* add an admissibility clause to §9. Existing evidence satisfies or narrows a gate when it records the SFM build/profile, input digests, method, and observed result for the exact fact the gate requires. Missing provenance fields narrow its scope rather than voiding it. Each item cites the gate clause it closes. Facts about pinned packages (E6) still require the pinned artifact.

**C2. Circular dependency between E6 and Stage 1** (F6/F22; §8.1, E6, Stage 0 "No production changes", Stage 1 dependencies). §8.1 says to inspect generator asset flow "in Scene, WinForms and test consumers." The Scene project doesn't exist until Stage 1, and Stage 1 depends on E6.

*Fix:* E6 qualifies asset flow on a throwaway copy of the Core/Scene/WinForms/test reference graph outside the product tree. Stage 1 re-verifies in the real tree, which its test list already does.

**C3. E1 needs an observation method that E7 provides** (F7/F29; E1, E7, Stage 0 objective). E1 runs first and must "record actual winner behavior." Reliable console capture, however, is an E7 deliverable.

*Fix:* qualify the logging method alongside E1, or state that E1 relies on distinctive visual winner fixtures that don't depend on logs.

**C4. The usefulness gate is measured at the wrong points** (F7/F8; §1.2, Stage 3 Done, Stage 6 Done). Stage 3 must show that "held-out normal sessions meet the accepted usefulness gate," but maps and audio don't arrive until Stage 6, and every real session has a map. Stage 6 Done has no measurement against the held-out corpus. As a result, the full first-public profile isn't re-measured until Stage 10, after the UI is built.

*Fix:* Stage 3 measures only the model/material subgraph. Add the held-out false-block measurement against the full profile to Stage 6 Done. State that the owner fixes the acceptance threshold when Stage 0 exits.

**C5. Severity of unknown VMT parameters is undefined** (F14, also F13; §7 table, §8.3, §8.1). §8.3 creates probable edges for unknown string parameters. §7 defines severity only for unknown *shaders*. That leaves three cases unspecified:

*Fix:* add explicit §7 rows for these cases, and add a VMT parameter/syntax census to the E2 corpus so the severity choice is evidence-based.

*Fix:* state that schema-1 changes add new optional members only, with no change to any member v1.0.4 knows, including nested `CreatorDefaults` and `RecentProjectEntry`.
